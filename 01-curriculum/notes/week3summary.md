Week 3 focused on Kubernetes security, identity, RBAC, workload hardening, secret management, supply-chain security, and service mesh concepts.
 In Lab 13, you learned the Kubernetes API request flow — Authentication, Authorization, and Admission — by inspecting your kubeconfig client certificate, identifying how CN maps to username and O maps to groups, using kubectl auth can-i for RBAC troubleshooting, and observing how admission controllers mutate and validate requests before objects are stored in etcd. 
 In Lab 14, you implemented least-privilege RBAC by creating a dedicated ServiceAccount, Role, and RoleBinding for a CI bot restricted to the prod namespace, then verified access boundaries both with impersonation and from inside a running pod using projected ServiceAccount tokens.
  In Lab 15, you explored container and pod hardening by comparing an insecure privileged root container against a hardened non-root container with dropped Linux capabilities, read-only filesystem, seccomp profile, and disabled privilege escalation, then enforced those standards cluster-wide using Pod Security Admission with the restricted policy level.
   In Lab 16, you learned the limitations of Kubernetes Secrets, understanding that Secrets are only base64 encoded by default and require additional protections such as RBAC, encryption at rest, External Secrets Operator integrations, or Sealed Secrets for real production security.
    In Lab 17, you practiced image security concepts by creating Docker registry image pull secrets, understanding private registry authentication flows, and learning the benefits of distroless images, image signing, and supply-chain verification.
     Finally, in Lab 18, you learned the service mesh mental model, understanding how sidecar proxies provide mTLS, traffic management, retries, observability, and service-to-service authorization, while also understanding when a mesh adds value versus unnecessary operational complexity. Overall, Week 3 built a strong foundation in Kubernetes security architecture, identity management, workload isolation, secret protection, and modern platform security practices used in real enterprise clusters.
